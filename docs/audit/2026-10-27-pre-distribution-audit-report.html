Product audit · pre-distribution · 27 Oct 2026

Agent File Optimizer, audited before its first public release

A small Cloudflare Worker that turns files into a temporary, readable link for an agent or a collaborator. The code is careful about secrets, storage, and deletion. The first-run path, the landing page's protection, and the public setup instructions are where it is not yet ready for strangers.

Verdict

Ready now for its owner and a few self-hosters who will read the stated limits. Ready for a small public group of self-hosters after Phase 0 and Phase 1. Not ready for strangers using a hosted instance, and the project does not offer one.

What is genuinely done: the storage model is careful. Tokens are 256-bit and stored only as hashes. Revocation and expiry turn access off before deleting content, and a failed deletion is retried. Public-repository import is allowlisted. The privacy document says what is not promised. The owner's own deployment has its admin gate working: a request without the token returns 401, and the full create, upload, read, MCP, and revoke cycle passed against the live Worker.

Three things in deployed code matter regardless of distribution. The landing page, where the admin token is typed, has no framing protection. Its inputs fail the non-text contrast requirement. And server errors are returned without being logged, so an outage would leave nothing to read.

Persona walkthroughs

1 · Primary operator (the owner, on desktop)

Delights

The page does one thing in three steps. Choosing a folder keeps relative paths. Copy and revoke sit beside the link. The failed-upload path keeps the link and says what to press next.

Stalls

The local run has no migration step, so the first request fails. The admin-token field sits on the page for everyone who visits it, and the expiry is shown only as a timestamp.

2 · Collaborator (a person who opens the share link)

Delights

The content is readable and the warning about bearer access is in plain words. The file list and the "Start here" section match what the page says.

Stalls

The page shows **1** and backticks and an ISO timestamp. There is no structure to scan, and the expiry is hard to read.

3 · Screen-reader user (an operator with assistive technology)

Delights

Each drop zone is a labelled control, the status region announces results, and focus is visible at 3 px with a 2 px offset. Reduced motion is honored.

Stalls

The only input that tells a sighted user where to type fails 1.4.11, and the same issue hides the disclosure controls on the site. A screen-reader user does not depend on that boundary, but a low-vision user does.

4 · External agent (the non-human reader)

Delights

The handoff says to read manifest.json first, lists each projection, and states what the link is. The MCP endpoint connected with the official SDK, negotiated down to 2025-03-26, and listed resources and tools.

Stalls

The MCP endpoint has been tested with one client and is described as experimental. The raw handoff is a text block, which is correct for an agent and unhelpful for a person.

GTM narrative and checklist

Narrative

Positioning: Agent File Optimizer turns a set of files into a temporary, readable link for an agent or a collaborator, and the link expires on its own.

Tagline (46 characters): Hand files to an agent, then let them expire.

First comment: I built this to stop explaining the same folder to an agent three times. You add files or a public GitHub repo, pick a one-, six-, or twelve-hour window, and get a link. The link serves the originals, a readable note, and a manifest that says what could not be read. It is open source and self-hosted, and it does not offer a hosted service.

Press paragraph: The project is a small Cloudflare Worker that makes a handoff for agents: originals, readable projections, a manifest of what was and was not converted, and a bearer link that stops working when its window closes. Its builder, R. Michael Thomas, states the limits plainly: PDF and Office extraction is basic, images have no text recognition, private repositories are not supported, and the read-only MCP endpoint was tested with one client.

Lead with three: the link that expires on its own; originals kept beside readable notes; limits stated in the handoff itself.

Do not talk about yet: "any file" and "zero retention" (both unverified as claims; PRIVACY.md says so); token savings (not measured); malware scanning (the basic check is a few heuristics, and it is labelled that way).

Competitive one-liners: Against a zip in a shared drive: the agent gets an orientation and a manifest, and the link ends by itself. Against tools that turn a repository into one prompt: this takes mixed folders and keeps the originals, but does not do private repositories. Against a hosted file-sharing service: you run it, and the storage sits in an account you hold.

Cohort metrics, without phone-home: count the rows in the workspaces table on your own deployment, by week, from the D1 console. Nothing is sent to the maintainer.

Retractions

Retracted: my first live check of the root returned 404. I had used curl -I, which sends HEAD; the Worker routes GET. A GET returned 200. The landing finding stands on the GET response.
Retracted: a grep for years returned "2024" and "2027" on the site and landing. Both are fragments of hex colours (#1d2024, #202719). No stale year is served.
Retracted: my first contrast table read the --file mode, which pairs every token with every ground, and showed accent ink on the page ground at 1.12:1 as a failure. That pair is never rendered. The table above uses rendered pairs only.
Tool defect (not a product finding): contrast.py --pairs skips every line that starts with #, so pairs written with hex colours are silently ignored and the run exits with an empty-table traceback. Workaround: drop the leading #. The script in the skill should treat # as part of the colour, not as a comment.

Not verified, needs a human

Cloudflare request-log retention of share paths (S-3). ZIP expansion on the live runtime (S-5). Whether private vulnerability reporting is enabled (S-7). The deployed cron's real cleanup behaviour, which needs a few days of observation. Performance numbers are estimates from the code, not measurements on Cloudflare. Other MCP clients were not tested.
