When the window ends

The clock is the point of the project, so this is the part to read closely.

What changes when the window ends

While the window is open

  • The share link can read: handoff.md, the manifest, the readable text, and your originals, as many times as needed.
  • The separate upload token can add files and revoke the link. The share link cannot.
  • The read-only MCP endpoint on the link answers. It is experimental.

After it ends, or once you revoke it

  • Every request returns 410 Gone at once, because the app checks expiry on every request. That includes the MCP endpoint.
  • The stored files and records are deleted on the next request or within 15 minutes, by the scheduled cleanup.

If you revoke the link, or a deletion fails

  1. You revoke the link. Access returns 410 Gone at once.
  2. The app deletes the file rows and every stored object before it reports success.
  3. If a deletion fails partway, access stays off, the workspace is marked as not yet purged, and the response to revoke says so.
  4. The next revoke or the scheduled cleanup retries until the purge completes.

What is not covered. Your hosting provider's own backups, logs, and retention policies sit outside the app, and the project does not promise secure erasure. "Zero retention" is a design goal, not a guarantee. Parsing runs inside your Worker, with no external processing by default. The full version is in PRIVACY.md.
