Open source · self-hosted · temporary

Hand files to an agent without the setup.

Agent File Optimizer turns a set of files into a temporary, readable workspace. You get one link. Whoever you share it with, human or agent, can read the originals and clear notes about them. When the window you chose ends, the link stops working and the content is deleted.

Read the code on GitHub Set up your own copy

There is no hosted service to sign up for. This project is software you run on your own Cloudflare account. Nothing here is a live public instance.

What it does

Sharing a folder of mixed files with an agent usually means explaining each file, converting some of them, and remembering which copy is current. Agent File Optimizer does that preparation once. It keeps your originals, adds readable versions where it can, and gives you a link to share.

How it works

  1. Add what to share

    Drop in files, choose a folder, or paste the address of a public GitHub repository.

  2. Choose a window

    Keep the link working for 1, 6, or 12 hours. You can also revoke it sooner.

  3. Share the link

    Copy the link and send it to the agent or person who needs the files. Anyone with the link can read the workspace until it ends.

What the agent receives

Originals

Every file as you added it, unchanged, under its original relative path.

A handoff note

handoff.md says what the workspace is for, when it expires, and what to read first.

A manifest

manifest.json lists each file with its hash, the parser used, a confidence level, and any warnings.

Readable notes

content.md and content.jsonl hold text from supported formats, and tree.txt shows the layout.

Who it is for

People who want a simple handoff to an agent or a collaborator, without remembering conversion commands, copying files around, or trusting a service with more than the window needs.

A file that cannot be converted is still included as its original. The upload response and manifest.json flag it with a warning. The project does not scan files for malware. It runs a small set of heuristic checks and labels them that way.

Privacy and trust

  • Short windows. A link lasts one, six, or twelve hours, or until you revoke it.
  • Bearer links. Anyone who has the link can read the workspace. Treat it like a password for those hours.
  • Deletion. When a workspace ends or is revoked, the app deletes its stored files and records. If a deletion fails, a scheduled cleanup retries.
  • What is not covered. Your hosting provider's own backups, logs, and retention policies sit outside the app. The project does not promise secure erasure.
  • No external processing by default. Parsing runs inside your Worker. An external parser exists only as an explicit, opt-in adapter.

The full, detailed version is in PRIVACY.md.

How to use it

Try it on your computer

Clone the repository, run npm install, then npm run dev. Open the local address Wrangler prints. Local mode uses simulated storage, which is fine for trying things out.

Run your own copy on Cloudflare

You need a Cloudflare account, an R2 bucket, and a D1 database. The README walks through the Wrangler steps, the admin token that keeps strangers from creating workspaces, and the dry run before deploying.

Connect an agent

Give the agent the share link. It should read handoff.md first. The link also exposes a read-only MCP endpoint for clients that support it. That endpoint is experimental.
